# 无限画布需求文档

## 1. 背景

当前项目已新增 `/canvas-lab` 实验页，使用 Excalidraw 作为无限画布底层能力。实验页已经具备基础画布、历史素材导入、本地保存、导出 JSON、清空画布等能力。

但当前实现仍属于 MVP：画布内容保存在浏览器本地 IndexedDB，不支持跨设备恢复；素材体系主要复用历史项目；生成流程和画布之间还没有形成闭环。后续需要将无限画布从实验页升级为可长期使用的产品功能。

## 2. 产品目标

无限画布要成为 AI 设计工作流的主工作台，用户可以在同一张画布中组织历史生成结果、参考图、提示词、任务状态和后续生成动作。

核心目标：

- 将生成结果从“列表式历史记录”升级为“空间化工作台”。
- 支持用户围绕项目持续迭代，而不是每次生成后只能下载或查看单张结果。
- 让画布成为后续生图、改图、局部重绘、扩图、视频生成的素材入口。
- 支持跨设备、长期保存和可恢复。

## 3. 当前状态

已完成：

- 新增 `/canvas-lab` 独立路由。
- 使用 Excalidraw 提供无限画布能力。
- 读取当前账号的历史项目。
- 支持将已完成/部分完成的生图项目导入为图片卡片。
- 支持将生成中、失败、视频等项目导入为状态卡。
- 本地 IndexedDB 自动保存画布。
- 支持刷新后恢复本地画布。
- 支持导出 Excalidraw JSON。
- 支持清空本地画布。
- 隐藏 Excalidraw 内置素材库入口，避免和项目素材库混淆。

当前限制：

- 画布不保存到 Supabase。
- 不支持跨浏览器、跨设备同步。
- 只支持单个本地画布。
- 历史项目默认只导入第一张图片。
- 画布无法直接触发生成任务。
- 生成完成后不会自动回填到画布。
- 图片文件以 base64 形式进入画布文件系统，长期容量风险较高。

## 4. 用户角色

普通用户：

- 查看历史生成结果。
- 将生成结果拖入画布整理。
- 基于画布素材继续创作。
- 保存长期项目画布。

设计师/重度用户：

- 管理多个项目画布。
- 在画布内沉淀参考图、提示词、版本对比和最终方案。
- 需要跨设备访问同一画布。

管理员/运营：

- 排查用户画布保存、素材导入、资源过期等问题。
- 评估画布带来的存储和带宽成本。

## 5. 功能需求

### 5.1 画布文档管理

优先级：P0

需求：

- 支持创建画布。
- 支持打开已有画布。
- 支持重命名画布。
- 支持删除画布。
- 支持一个用户拥有多个画布。
- 支持最近打开画布自动进入。
- 支持画布列表展示：名称、更新时间、缩略图、素材数量。

验收标准：

- 用户在 A 设备创建画布后，B 设备登录同一账号可以看到。
- 删除画布不会删除历史生成项目。
- 画布列表能正确按更新时间排序。

### 5.2 云端自动保存

优先级：P0

需求：

- 将画布 scene 数据保存到 Supabase。
- 自动保存 elements、appState、文件引用信息。
- 保存状态展示：保存中、已保存、保存失败。
- 支持保存失败后的重试。
- 本地 IndexedDB 作为离线缓存和兜底。

验收标准：

- 用户编辑画布后，刷新页面不丢失。
- 换浏览器登录后可以恢复同一画布。
- 断网或保存失败时给出明确提示。

### 5.3 画布版本恢复

优先级：P1

需求：

- 定期保存版本快照。
- 支持查看最近版本。
- 支持恢复到某个历史版本。
- 支持恢复前确认。

验收标准：

- 用户误删元素后，可以从历史版本恢复。
- 恢复动作不会破坏原历史项目数据。

### 5.4 历史素材导入

优先级：P0

需求：

- 支持导入单张历史图片。
- 支持一个项目的多张结果图逐张导入。
- 支持批量导入同一项目的全部图片。
- 支持视频项目导入为视频卡片，包含封面、状态、打开结果页链接。
- 支持失败项目导入为错误说明卡。
- 防止同一个素材重复导入。

验收标准：

- 多图项目可以导入全部结果。
- 视频项目不会触发图片下载失败。
- 重复点击导入时，画布定位到已导入元素。

### 5.5 本地素材上传

优先级：P1

需求：

- 支持用户上传本地图片到画布。
- 支持拖拽图片文件到画布。
- 支持上传前大小和类型校验。
- 支持上传后进入 Supabase Storage，避免只存在本地。

验收标准：

- PNG、JPG、WEBP 可正常上传。
- 超过大小限制时有明确提示。
- 刷新和跨设备后图片仍可显示。

### 5.6 画布到生成流程

优先级：P0

需求：

- 选中画布图片后，可以作为参考图发起生图。
- 支持从画布元素创建生成任务。
- 支持将画布中的文本卡作为 prompt。
- 支持跳转或打开生成参数面板。
- 生成任务创建成功后，在画布中插入任务占位卡。

验收标准：

- 用户可以从画布选中图片进入现有生图流程。
- 新任务状态可以在画布中看到。
- 不影响现有主页生成流程。

### 5.7 生成结果回填画布

优先级：P0

需求：

- 从画布发起的生成任务完成后，自动将结果插入原画布。
- 支持任务失败后更新状态卡。
- 支持部分完成时显示已完成图片和失败说明。
- 支持用户手动刷新任务状态。

验收标准：

- 从画布发起任务后，不需要回历史页手动找结果。
- 任务完成后画布自动出现结果图片。

### 5.8 画布内操作体验

优先级：P1

需求：

- 优化工具栏和素材栏布局。
- 精简 Excalidraw 中与产品无关的功能入口。
- 支持右侧素材栏搜索和筛选。
- 支持按项目、类型、状态筛选素材。
- 支持画布空状态引导。
- 支持移动端基础查看和导入。

验收标准：

- 用户不会误点 Excalidraw 公共素材库。
- 历史素材超过 50 个时仍能快速找到目标素材。
- 移动端不出现关键按钮遮挡。

## 6. 非功能需求

### 6.1 性能

- 首屏加载不应明显拖慢当前主站。
- `/canvas-lab` 应继续使用客户端动态加载 Excalidraw。
- 画布保存应防抖，避免每次鼠标移动都写入数据库。
- 大图应优先保存文件引用，不应长期将 base64 大量写入数据库。

### 6.2 稳定性

- 保存失败不能导致画布崩溃。
- 下载失败需要展示具体错误原因。
- 图片资源过期时，应显示占位卡并保留项目元数据。
- IndexedDB 损坏时，应允许用户打开空白画布并重新同步云端。

### 6.3 安全

- 所有画布数据必须按用户隔离。
- 画布 API 必须校验 Supabase 登录态。
- 下载代理继续使用安全 URL 校验，防止 SSRF。
- 不允许用户读取其他账号画布或 Storage 文件。

### 6.4 成本

- 需要限制单画布最大文件体积。
- 需要限制单用户画布数量。
- 图片文件应尽量复用已有 Supabase Storage URL。
- 云端版本快照需要保留策略，避免无限增长。

## 7. 建议数据模型

### 7.1 canvas_documents

字段建议：

- `id`: UUID
- `user_id`: UUID
- `title`: text
- `scene`: jsonb
- `app_state`: jsonb
- `thumbnail_url`: text
- `created_at`: timestamptz
- `updated_at`: timestamptz
- `deleted_at`: timestamptz nullable

说明：

- 保存画布主文档。
- `scene` 保存 Excalidraw elements 和轻量文件引用。
- 不建议直接把大量 base64 图片长期存入该表。

### 7.2 canvas_assets

字段建议：

- `id`: UUID
- `canvas_id`: UUID
- `user_id`: UUID
- `source_type`: text
- `source_project_id`: text nullable
- `source_task_id`: text nullable
- `storage_url`: text
- `mime_type`: text
- `width`: integer
- `height`: integer
- `created_at`: timestamptz

说明：

- 管理画布引用的图片、上传素材和生成结果。
- 支持素材去重和资源恢复。

### 7.3 canvas_versions

字段建议：

- `id`: UUID
- `canvas_id`: UUID
- `user_id`: UUID
- `scene`: jsonb
- `created_at`: timestamptz
- `reason`: text

说明：

- 保存历史版本。
- 可以按数量或时间滚动清理。

## 8. API 需求

建议新增接口：

- `GET /api/canvas-documents`：获取当前用户画布列表。
- `POST /api/canvas-documents`：创建画布。
- `GET /api/canvas-documents/[id]`：获取画布详情。
- `PATCH /api/canvas-documents/[id]`：保存画布。
- `DELETE /api/canvas-documents/[id]`：软删除画布。
- `POST /api/canvas-documents/[id]/assets`：上传或绑定素材。
- `GET /api/canvas-documents/[id]/versions`：获取版本列表。
- `POST /api/canvas-documents/[id]/restore`：恢复版本。

所有接口必须：

- 校验登录态。
- 校验 `user_id` 归属。
- 返回结构化 JSON 错误。
- 记录关键错误日志。

## 9. 里程碑

### M1：云端保存基础版

目标：从本地实验页升级为可跨设备恢复。

范围：

- Supabase 表结构。
- 单画布云端保存。
- 自动保存。
- 云端恢复。
- 保留 IndexedDB 缓存。

### M2：多画布和素材导入增强

目标：支持项目级长期使用。

范围：

- 画布列表。
- 新建、重命名、删除画布。
- 多图项目导入。
- 视频卡片。
- 素材搜索筛选。

### M3：画布触发生成

目标：打通画布和生成流程。

范围：

- 选中图片作为参考图。
- 文本卡作为 prompt。
- 从画布创建任务。
- 任务占位卡。

### M4：生成结果自动回填

目标：形成完整创作闭环。

范围：

- 任务状态同步。
- 完成结果自动插入画布。
- 失败状态回填。
- 手动刷新任务。

### M5：版本、容量和产品化

目标：提升长期稳定性。

范围：

- 版本恢复。
- 画布缩略图。
- 容量限制。
- 大图引用优化。
- 移动端体验优化。

## 10. 验收清单

P0 验收：

- 用户可以创建并保存一个云端画布。
- 用户刷新页面后画布不丢失。
- 用户换设备后可以打开同一画布。
- 用户可以从历史项目导入图片。
- 用户可以导入多图项目中的任意一张图。
- 用户可以从画布选中图片发起生成。
- 从画布发起的任务完成后，结果能回填画布。
- 主工作台、历史页、充值页不受影响。

P1 验收：

- 用户可以管理多个画布。
- 用户可以恢复历史版本。
- 用户可以上传本地素材。
- 用户可以搜索和筛选素材。
- 大画布不会频繁保存失败。
- 图片过期时画布仍保留可理解的占位信息。

## 11. 风险与决策点

### 11.1 是否继续使用 Excalidraw

建议继续使用。当前它已经满足基础无限画布、缩放、拖拽、元素编辑、导入图片、导出等需求。短期不建议自研画布引擎。

需要接受的限制：

- Excalidraw 内置 library 不适合作为 AI 图片素材库。
- 深度定制 UI 会受到 Excalidraw 内部结构限制。
- 图片和文件持久化需要自行设计。

### 11.2 是否保存 base64

不建议长期保存大量 base64。MVP 可以保留，但云端版本应改为 Storage URL + 文件元数据。

### 11.3 是否加入多人协作

当前不建议进入第一阶段。多人实时协作会显著增加复杂度，应在单人云端画布稳定后再评估。

## 12. 下一步建议

下一阶段优先做 M1：云端保存基础版。

推荐实施顺序：

1. 设计 Supabase 表结构和 RLS。
2. 新增画布 CRUD API。
3. 将 `/canvas-lab` 从 IndexedDB 主存储改为 Supabase 主存储。
4. IndexedDB 保留为本地缓存。
5. 完成跨设备恢复验收。
